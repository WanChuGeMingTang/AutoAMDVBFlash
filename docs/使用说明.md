# AutoAMDVBFlash 使用说明

> 本脚本由「玩出个名堂——更具温度的怀旧数码玩乐指南」制作（运行时以暗黄色显示：醒目但不刺眼）

| 文件 | 作用 |
|---|---|
| `AutoAMDVBFlash.bat` | 主脚本，中文界面（GBK 936） |
| `AutoAMDVBFlash-EN.bat` | 主脚本英文版（纯 ASCII，任意代码页可用，功能完全相同） |
| `选择刷写器.bat` | 选版本（中文提示） |
| `Choose-Flasher.bat` | 选版本（English prompts） |
| `flasher.txt` | 当前固定的刷写程序（一行文件名，可删） |
| `driver\` | AmdTools64 驱动及加载/卸载脚本 |
| `Software\` | 放 `amdvbflash*.exe` |
| `vbios_backups\` | VBIOS 备份 + `flasher_out.log` 刷写程序原始输出 |

## 一、功能

| 项目 | 说明 |
|---|---|
| 刷写程序 | 自动识别 `amdvbflash*.exe`，任意 5.x 版本均可，不写死版本 |
| 搜索顺序 | ①脚本目录 → ②`.\Software` → ③`..\Software` |
| 多版本 | 命中的目录里，文件名数字最大的版本自动胜出 |
| 提权 | 脚本自己生成提权助手（PowerShell，缺 PS 时回退 VBScript），弹 UAC |
| 目录改名/移动 | 完全支持，含空格、括号、中文路径 |
| 固定版本 | `选择刷写器.bat` / `Choose-Flasher.bat`，写入 `flasher.txt` |
| 刷写输出 | 先写入 `vbios_backups\flasher_out.log`，再完整显示（避免命令行引号问题） |

流程：加载驱动 → 备份 VBIOS → （拖入 `.rom` 时）强刷 → 卸载驱动。

## 二、命名规则（重要）

刷写程序请命名为 **`amdvbflash*.exe`**，例如：

```
amdvbflash.exe
amdvbflash5.0.638.exe
amdvbflash_879_Moded_v1.exe
amdvbflash_879_Moded_v2.1.exe
```

> 注意：是 `.exe`，不是 `.rom`。`.rom` 是显卡 BIOS 固件，由鼠标拖到脚本上使用。

## 三、搜索顺序与自动选择

**先看脚本自己所在的目录**，找不到再去 Software 目录：

1. `AutoAMDVBFlash\`（脚本目录，优先）
2. `AutoAMDVBFlash\Software\`
3. `AutoAMDVBFlash\..\Software\`

第一个有 `amdvbflash*.exe` 的目录生效；同一目录里多个版本时，**文件名数字最大的那个胜出**：

```
amdvbflash.exe                  -> V0000
amdvbflash_moded_02.exe         -> V0002
amdvbflash5.0.638.exe           -> V000500000638
amdvbflash_879_Moded_v1.exe     -> V08790001
amdvbflash_879_Moded_v2.1.exe   -> V087900020001
```

脚本启动时会打印实际用的是哪个：

```
Flasher : amdvbflash_879_Moded_v1.exe
Location: D:\WCGMT\AutoAMDVBFlash\Software\amdvbflash_879_Moded_v1.exe
```

## 四、固定使用某个版本

- **中文界面**：双击 `选择刷写器.bat`
- **英文界面**：双击 `Choose-Flasher.bat`

两者都会列出所有目录里找到的版本（带版本键和所在目录），输入序号即可；输入 `0` 恢复自动选择，直接回车取消。
选择结果写入脚本目录的 `flasher.txt`（只有一行文件名），删掉它效果等同 `0`。

## 五、可选参数（一般用不到）

| 参数 | 作用 |
|---|---|
| `--selftest` | 只显示识别结果，不做任何操作 |
| `--list-flashers` | 列出当前会使用的刷写程序完整路径 |
| `--choose-flasher` | 交互式选择版本（`Choose-Flasher.bat` / `选择刷写器.bat` 调用的就是它） |
| `--no-driver` | 跳过驱动加载/卸载（驱动已加载或排错时用） |

## 六、使用方式

- **备份 VBIOS**：双击脚本（或右键「以管理员身份运行」）
- **强刷固件**：把 `.rom` 文件从任意文件夹拖到脚本图标上

备份文件保存在 `vbios_backups\`，名字形如
`Navi23_<时间>_bus03_pn<BIOS P/N>.S02.rom`。

### 跨型号 ROM 的二次确认（跨品牌不再强刷）

普通刷写带 `-fv`（允许降级）。如果刷写程序以
`SSID mismatch`、`PartNumber mismatch` 或 `is not same` 拒绝，脚本会先把它自己报的错原文打出来，
再要求输入 `Y` 确认，然后改用

```
-fv -fp      （版本 / PartNumber 两项检查绕过；SSID 不绕过）
```

强制刷写。输入其它内容即放弃，显卡不受影响。

> **跨品牌不在强刷范围内**：脚本不传 `-fs`，所以 `0xA00003FE SSID mismatch` 即使确认后仍会被刷写程序拒绝，
> 只能换成本品牌/本型号对应的 ROM。
>
> 5.0.879 的错误码对照：`0xA00003FE` SSID 不匹配（-fs）、`0xA00003FF` PartNumber 不匹配（-fp）、
> 版本比现有低用 -fv、镜像完全相同用 -fa。脚本用的是 `-fv -fp` 组合。

### 镜像与当前完全相同时

刷写程序报 `0xA00003FC Same IFWI image already flashed`（说明拖进来的 ROM 和卡上现有的一模一样），
脚本会列出两边的 IFWI 版本，并询问是否用 `-fa` 再刷一遍：

- 输入 `Y`：强制重刷同一镜像 —— **AMD 官方要求两个 SPIROM 分区各刷一次**，
  第一次刷完重启后，第二次就会命中这个提示，用它写第二个分区
- 其它任意键：放弃，显卡不动（默认行为）

## 七、注意事项

1. **提权**：脚本会弹 UAC，必须点「是」。若被拒绝，窗口会提示，不会做任何修改。
   备用办法：给脚本建快捷方式 → 属性 → 勾选「以管理员身份运行」，然后往**快捷方式**上拖 `.rom`。
2. **文件夹可随意改名/移动**：`driver`、`Software`、两个选择器脚本要和主脚本在一起；只拷主脚本而不带 `driver` 目录会报错。
3. **驱动**：用目录里 `driver\` 自带的 AmdTools64 即可，实测 5.0.879 系列也能正常识别并备份，
   不需要 TechPowerUp 的 `AMDVBFlashDriverInstaller.exe`（同类驱动的另一个封装，可作备用）。
4. **`vbios_backups\flasher_out.log`** 是最近一次刷写程序的原始输出，出错时看它最直接。
5. 脚本文件是 **GBK（936）编码**，用记事本修改时请另存为 ANSI/GBK，否则中文提示会乱码。
6. 换用未魔改的 `amdvbflash.exe`（879 原始版）同样直接放进目录即可，只是它不支持跨品牌/跨型号混刷；
   脚本层面的强刷流程（`is not same` 处理）仍会走。

## 八、语言版本

两个主脚本由同一份源码生成，功能完全一致，只是界面语言不同：

| 文件 | 界面语言 | 编码 | 适用 |
|---|---|---|---|
| `AutoAMDVBFlash.bat` | 中文 | GBK 936（脚本自己 `chcp 936`） | 中文 Windows |
| `AutoAMDVBFlash-EN.bat` | 英文 | 纯 ASCII，无需切换代码页 | 英文 Windows / 分享给国外用户 |

- 英文版把署名译作 `Made by WanChuGeMingTang - the warmer guide to retro digital fun`
- 中文版在**英文系统**上也能跑（已实测：CP437 控制台下完整跑通备份+刷写），只是中文提示会显示成乱码/方框
- 主脚本文件是 GBK 编码，用记事本修改时请另存为 ANSI/GBK

## 九、要不要进安全模式

**不必进安全模式，正常 Windows 下即可。** 依据：

- 官方 changelog 5.0.572：`Updated tool with support added on Windows for flashing with AMD GPU driver installed`
- 官方 readme 的要求是「**刚重启完就刷**」，不是安全模式
- 你之前安全模式那次失败是 `PartNumber mismatch` 校验拦截，与运行模式无关

比安全模式更重要的是这三条：

1. 刷之前**重启**，刷完按提示**重启**
2. 关掉显卡监控/超频类软件（Afterburner、HWiNFO、GPU-Z 轮询等）
3. **刷两遍**（两个 SPIROM 分区），中间重启一次

什么情况才退到安全模式：正常模式下出现非校验类的怪错误（`Generic failure`、识别不到卡等）。
安全模式下驱动仍可用 `devcon` 手动安装（已验证），但每次都要重新进。
